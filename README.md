# PCPX packages

The zero-knowledge encryption primitives behind [pcpx.one](https://pcpx.one) —
as versioned, auditable npm packages instead of live-served web JavaScript.

| Package | What it is | npm |
|---|---|---|
| [`@pcpx/sdk`](packages/sdk) | Crypto + link format (AES-256-GCM, PBKDF2-SHA256), browser / worker / Node 20+, zero runtime deps | [`@pcpx/sdk`](https://www.npmjs.com/package/@pcpx/sdk) |
| [`@pcpx/cli`](packages/cli) | One-time secrets from scripts and CI — command `pcpx` | [`@pcpx/cli`](https://www.npmjs.com/package/@pcpx/cli) |

```sh
npm install @pcpx/sdk       # library
npm install -g @pcpx/cli    # CLI, command: pcpx
```

## The format is specified, not just implemented

[`docs/PCPX1-ENC-v2.md`](docs/PCPX1-ENC-v2.md) describes the container format
**byte for byte**: container, key derivation, AAD binding, payload layer, link
format, and the checks a conforming reader must perform.

[`tests/vectors/pcpx1-enc-v2.json`](tests/vectors/pcpx1-enc-v2.json) holds test
vectors — passphrase, salt, derived key, IVs, container size and SHA-256. A new
implementation checks PBKDF2 against `derivedKeyB64u` first; if that matches,
the rest is framing.

The vectors are generated by [`tools/spec/build-vectors.mjs`](tools/spec/build-vectors.mjs)
**without the SDK** (node:crypto only), so nothing is checked against itself.

## Why this exists

The encryption used to live only in the website's JavaScript. Any additional
client would have to re-implement it, and every re-implementation is a chance to
subtly break the format. Now there is exactly one implementation — and a spec so
others don't have to guess.

See [pcpx.one/sdk](https://pcpx.one/sdk), [pcpx.one/cli](https://pcpx.one/cli)
and [pcpx.one/warum](https://pcpx.one/warum).
